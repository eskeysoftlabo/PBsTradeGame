# 交易拠点育成 — Phase 1 調査・設計

2026-09-28 / 調査対象 v0.18.9、SavedVariables schema 10。
本書は実装前の設計。以下の初期数値はPhase 6で検証する候補であり、調整済みの値ではない。

## 現行システムの確認

- Config.lua：経済・交渉・内政の調整値。C.Moneyは元の値を10,000倍する。新施設の金額は実ゴールドで算出し、二重換算を避ける。
- Data.lua / World.lua：53地域、基本物件1,303件、物件カテゴリ16種、商会・本社・章目標。実在地点はLiveCatalogによって動的に追加されるので、全件登録を解禁条件にしない。
- Model.lua：状態生成、所有物件、資産・ランキング、買収評価、章進行、決算、保存と移行を担う。M.Newは定義を複製する。
- Engine.lua：ESO APIから独立したリアルタイム交渉。乱数注入可能。構え、重要交渉の段階強化、COMグループ調達、実際の資金残高による上限が実装済み。
- Controller.lua：実際の順序は買収→防衛判定→内政→ランキング→決算。内政は3行動。決算後に敵同士の取引、章進行、10期ごとの交易会議を処理する。
- UI.lua：2DのControl、Texture、Labelによるフルスクリーン。ゲームパッド入力をControllerへ転送。基準座標をリサイズする方式。金貨やポップアップの描画階層は既に分離。
- Main.lua / Model.Export・Load：アカウント共通SavedVariables。状態を遅延保存し、安全な画面遷移等でFlushSave。stateFieldsへテーブルを単純追加すると参照共有になるため、拠点は専用の深いコピーで保存する。
- マニフェスト：txtとaddonの内容一致が必須。package.pyは全Lua/XML/DDSの列挙、DDS形式、バージョン一致を検査する。
- 検証：tests/run.lua、tests/ui.lua。既存キャンペーン試算は買収を一部抽象化しているため、新障壁の交渉難易度検証にはEngineを直接使う追加試算が必要。

## プレイの流れ

第3章開始時に導入を一度表示し、内政メニューへ「交易拠点」を追加する。
従来の3行動は維持し、拠点の建設は別の工事枠で管理する。閲覧・配置計画の操作で内政行動を消費しない。
拠点を開かず内政を終了しても、決算で工事・収支・成長・イベントが進む。
経営タブから常時閲覧可能とし、建設・移設等の変更は内政中に限る。交渉中に能力を変更できない。
期スキップ時も同じ決算経路を使う。画面の開閉、UI再読込、ゲーム外の経過時間では進行しない。

## モジュール構成

| 追加モジュール | 責務 |
| --- | --- |
| HubData.lua | 施設、隣接、地区、方針、イベント、敵障壁プロファイル、数値設定 |
| Hub.lua | ESO/UI非依存の状態生成・検証・操作・1期進行・能力計算・補正算出 |
| HubController.lua | カーソル、建設カタログ、移設プレビュー、内政への戻り先、操作結果 |
| HubUI.lua | 固定数の描画コントロール、疑似クォータービュー、選択・建築・地区演出 |
| scripts/simulate_hub.lua | 配置方針と乱数を固定した長期・交渉比較、CSV結果 |
| tests/hub.lua | 状態、保存、費用、隣接、地区、期進行、障壁の回帰検証 |

読み込み順：Config/Data/World → HubData/Hub → Model → 既存Engine/Controller → HubController/HubUI → UI/Main。
HubはModelを直接呼ばず、所有カテゴリ・地域・章・商会資金等をまとめたcontextを受け取る。
経済差分はModel経由で一度だけ反映し、表示側は状態を変更しない。

## 状態と保存

```lua
state.hub = {
    version = 1,
    unlocked = false,
    introSeen = false,
    landTier = 1,
    nextBuildingId = 1,
    buildings = {
        -- {id=1, type="market", x=2, y=2, level=1,
        --  status="building", remainingPeriods=2, paidCost=...}
    },
    policy = "balanced",
    growth = 0,
    lastSettledCycle = 0,
    rngState = 1,
    unlocks = {},
    activeEvents = {},
    log = {},
}
```

能力値・隣接・地区・占有グリッドは再計算可能な派生値としてキャッシュし、保存しない。
保存スキーマを11へ更新。既存hubなしは初期値で補完し、第3章以降の旧セーブにも解禁する。
初期値は現在のcycleをlastSettledCycleへ設定し、過去数百期の収益を遡及支給しない。
範囲外座標、重複配置、未知施設、負数、NaN、無限大を検証。未知データは退避し、ロード時に金銭を自動返還しない。
旧物件の所有権、資金、章、実在地点登録を変更しない。保存→新しいLua環境で復元する試験を行う。
イベント用の独立した乱数状態を保存し、UI再読込による引き直しと既存COM乱数列への干渉を防ぐ。

## 建設と能力

初期4×4、拡張6×6、最大8×8を候補とする。全施設は初版では1マス。
建設2期、高度施設3期、異界施設4期、同時工事2枠を初期候補とし、設定テーブル化する。
建設費は注文時に固定する。現在の物件平均価格と章別基準を参照し、工事中の値上がりで追加請求しない。
維持費と施設価値は支払済み建設費を基準にし、投資の自己増殖を避ける。資産へ算入する場合も回収可能額だけとし、総資産を参照して費用を再帰的に増加させない。
資金不足時は設定した低優先施設から休止し、強制借金や毎期の確認ダイアログを発生させない。
撤去の返還率・移設費・工事取消返還率を別定義し、移設中は能力停止。確定前のキャンセルは無料。

| 章 | 主な施設 | 主能力 |
| --- | --- | --- |
| 3 | 銀行、市場、倉庫、キャラバン宿、酒場、工房、商館 | 資本、商業、物流、情報、影響 |
| 4 | 証券取引所、情報局、大使館 | 金融・諜報・外交の専門化 |
| 5 | 次元交易門、エセリアル市場、次元銀行、デイドラ契約所、オブリビオン商館 | 異界交易と複合能力 |

本編で所有する物件カテゴリと地域数を設計図の条件にする。例：工房物件で上位工房、港湾・キャラバンで物流施設、魔術施設で異界施設。
基本5能力は第3章の通常施設だけで揃う。特殊な実在地点への訪問を必須にしない。
一度得た設計図は失わないが、供給元物件の所有数による稼働ボーナスは売却・喪失で変化する。
同種施設の過密には能力逓減と維持費を設け、少ない土地での混成配置を有利にする。

## 隣接と地区

隣接はマンハッタン距離1。施設ペアごとに一度だけ計上し、配置走査の順序に依存させない。
市場＋倉庫、銀行＋証券取引所、酒場＋情報局、工房同士等をデータ定義する。
地区は第4章以降。条件を満たす連結施設群から金融街、交易区、工業区、諜報区、外交区を判定する。
同じ施設を複数地区に重複所属させず、優先順位と施設IDで決定的に解決する。
同地区の重複加算上限、必要施設数、最大有効地区数を設定化。最高効果には複数マスが必要で、最大64マスでも全地区の最大化は難しくする。
移設プレビューに成立・消滅する地区を表示。新成立時だけ帯と効果音を出す。

## 買収・防衛との接続

敵商会ID別の上書き＋既存性格別既定値で5種の障壁を定義し、第3章以降の主要商会・本社に適用する。
未知の通常商会や中立物件にボス用補正を付けない。

| 拠点能力 | 対象障壁 | 戦闘への効果 |
| --- | --- | --- |
| 資本力 | 資本防壁 | 投入額の有効圧力を改善 |
| 商業力 | 地域支持 | 長期交渉の疲弊を軽減、収支改善 |
| 物流力 | 物流支配 | 相手の増援テンポ・防衛補正を緩和 |
| 情報力 | 情報防衛 | 相手の駆け引き耐性を緩和、詳細値の開示 |
| 影響力 | 政治的影響力 | 交渉の評価基準額の上乗せを緩和 |

能力と障壁の比率で連続的に補正する。能力0でも有限倍率で買収可能、十分な能力でも自動勝利にはならない。
障壁の未突破分による追加不利は初期候補として最大+50%、育成側の単一効果は最大20%程度とし、既存の構え・重要交渉・COMグループ技との積み重ねを実戦試算で制限する。
資金投入補正は会計上の拠出額を増やさず、交渉圧力だけへ適用。金貨表示・消費資金・予算の整合性を維持する。
敵の追加出資は必ず現金・物件調達余力内。拠点障壁を理由に無限予算を与えない。
障壁対策前後の見積もりを共通関数で算出し、詳細・開始確認・Engineで食い違わせない。
戦闘開始時に能力・障壁補正を固定し、毎フレーム地区検索しない。既存の構えを拠点だけで自動消去しない。
防衛時は物流による対応速度・情報による敵工作耐性などに別上限を設け、後半の攻勢を無力化しない。
第4章以降の敵対抗策は事前に確認できる得意障壁・期間限定妨害として定義し、施設の突然の全損や永久停止を避ける。

## 決算・イベント

M.SettleCycle内で対象cycleを渡してHub.Settleを一度呼ぶ。
既存物件収益→拠点収益/維持費→負債返済→現金反映→物件成長→期確定の順序を明示し、返却レポートへ拠点欄を追加する。
工事完了した施設は次期から収益を出す。方針・イベントの残期間減算順も固定する。
都市成長は稼働・多様性・所有物件との接続で進み、土地拡張や装飾段階へ反映する。
イベントは交易ブーム、火災、盗賊、新交易路、商人流入、疫病、戦争特需、物資不足、人材、密輸提案、デイドラ商談をテーブル定義する。
初期確率候補8%/期、最低間隔5期。既定方針で自動対処し、任意の提案だけ次の内政で確認できる。
イベントの効果量・持続・被害上限を有限にし、ログ件数も制限。通知は決算へまとめる。
密輸・デイドラの提案は既定で辞退し、明示選択時だけ高収益と代償を受ける。
市場への効果は専用の期間限定補正として合成し、既存の交易会議イベントを上書きしない。

## UI・操作・描画

左約2/3を俯瞰都市、右約1/3を施設詳細・能力・収支・建設カタログにする。
投影は screenX=(x-y)*tileWidth/2、screenY=(x+y)*tileHeight/2。描画順はx+y、同値時xで固定。
建物は床・壁・屋根の2D部品/同梱DDSで構成。影と高さ、工事足場、レベル別装飾、異界施設の発光で成長を見せる。
既存API利用箇所の調査ではControl/Texture/Labelとアンカーによる実装が可能。任意ポリゴンや3D APIの存在は前提にせず、必要な新APIはPhase 2で契約確認する。
既存木枠・紋章・背景を再利用し、新しいタイル/建物素材は同梱する。新ライブラリ・外部ダウンロードは要求しない。
描画階層：地面→地区ハイライト→建物/影→カーソル→詳細/文字→モーダル。金貨画面の階層を変更しない。
最大64マスの固定コントロールプールを使い、非表示時は描画更新しない。地区/能力は編集・所有変化・決算時だけ再計算。

- 十字キー/左スティック：画面方向に近い隣マスへ。建設カタログ内ではリスト選択。
- ×：選択・建設/移設確定。○：プレビュー取消・内政へ戻る。
- L1/R1：建設・施設操作・方針の分類切替。□：操作ガイド。△：施設/地区詳細。
- マウスでも同じ操作。ゲームパッドで全機能に到達することを必須とする。
- 施設詳細：名前、レベル、状態、5能力、維持費、隣接、地区、アップグレード条件、費用と必要期数。
- 画面下へ全マスを押し込まず、最大拡張時はカメラ追従/縮尺を使う。テレビ距離で読める既存日本語フォントを使う。

## Phase別の実装と合格条件

1. 調査・設計（本書）：統合点と状態形式を確定。既存コア/UIテストをbaselineとして実施。実行コードは変更しない。
2. 最小プロトタイプ：HubData/Hub、4×4地図、基本5能力、配置と選択、決算進行、旧セーブ補完、内政への往復。0.19.0系を予定。境界、資金不足、取消、再ロード、二重決算防止と既存回帰を検証。
3. 配置ゲーム：アップグレード、撤去、移設、土地拡張、隣接、地区。重複計上・重複占有・返金悪用・地区消滅を検証。既存回帰を実行。
4. 本編連動：設計図と所有物件、敵障壁、攻防補正、詳細表示。章1～2が従来と一致すること、資金だけで突破可能なこと、重要交渉が手動で残ることをEngine試験。既存回帰を実行。
5. 運営と表現：方針、イベント、章4/5施設、成長外観、工事/地区演出、解禁案内、SE。各解像度と描画階層を検証。ESO実機の入力・フォント・DDSはモックと区別して報告。
6. バランス・最適化：放置/単一施設/混成/敵弱点特化を同じ初期状態・乱数で比較。500～1,000期を複数seedで試算し、重要交渉はEngineで実行。配置、政策、費用、対策効果を調整して回帰・パッケージ検査。

各Phase完了時に実装内容、テスト方法/結果、未解決問題、次の確認事項を報告する。
Phase 6の出力は章到達期、最終資産、拠点への支出・利益、操作回数、攻防敗北率、施設/地区分布、計算時間。
「都市へ5期投資した時」と「20期資金を貯めた時」の同一敵への結果を比較し、特化が実際に有利か検証する。数字は目標例であり、未検証の達成値として扱わない。
既存のクリア試算は抽象化部分を明記し、実機プレイ時間や勝率と同一視しない。
